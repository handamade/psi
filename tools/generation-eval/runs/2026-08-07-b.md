## The four assessed docs gaps

1. **`onSortChange`'s contract is undocumented, and the agent read generated JS to find it.**
   Nothing in `docs/Table.md` or the manifest says whether the callback emits the *current* or
   the *already-toggled* direction, so the agent grepped `dist/index.js` to settle it. That is
   permitted — `dist/` is fair game — but a consumer should not have to read a bundle to learn
   what a callback hands them. **The most substantive finding of this run.**
2. **`data-table` never says what the actions column's `<th>` should contain.** The pattern's
   content says "put the row-actions menu in the last cell" and stops. The agent chose a visible
   "Actions" header. This is the second run to hit it — 08-07 (a) reported the same thing as
   the absence of a visually-hidden affordance.
3. **Spacing guidance covers forms only.** `llms.txt` gives 24/12/8 for fields, toggle groups
   and button rows, and says nothing about page-level layout, so every section gap was the
   agent's choice. Correctly tokenised (`psi-gap-24`, `psi-py-32`), but unguided.
4. **`Pagination` is silent on a `page` that exceeds a shrinking `pageCount`.** The agent
   clamped. 08-07 (a) hit the adjacent `pageCount === 0` case. Recurring.

Two smaller, both recurring and both left uncounted: running N controlled `Menu`s (the D58
invariant is documented, the N-instance idiom is not — the agent again invented a single
`openMenuId`), and `.psi-m-0` going undiscovered, so UA margins were killed with inline
`margin: 0` where 08-07 (a) found the utility.

### Not counted

Pattern *parameters* — `action-feedback`'s variant, `row-actions`' placement,
`tabbed-workspace`'s orientation — are questions the patterns exist to ask; answering them is
the intended flow, not a docs gap. Nor are the task-driven trims (dropping `bulk-action-bar`'s
Export/Delete, `detail-drawer`'s Save), the theme choice, or app-level content decisions.

One deliberate divergence, disclosed by the agent and correct: `row-actions` says to hand a
destructive item to `destructive-confirm`, but the task specified a transient Undo instead, so
`Void` goes to `action-feedback`. Following the task over the pattern was right.

## Method caveat, unchanged and restated

The agent was context-free but ran **inside the repo**, so `CLAUDE.md` loaded — and it states
the px size vocabulary, the flat variant list, the no-hardcoded-colours rule and the
five-stylesheet rule. `PROMPT.md` permits agent-facing docs and every prior run had the same
condition, so the trend is comparable. But this measures **the trail plus `CLAUDE.md`**, and a
clean hard-fail score should be read that way.

Now that `pnpm verify:published` exists (D75), a stricter variant is finally cheap: run the
task in a scratch project with the package installed from npm and no repo present. That would
measure the published artifact alone. Worth doing before treating "zero hard fails" as a
property of the trail rather than of the repo.
