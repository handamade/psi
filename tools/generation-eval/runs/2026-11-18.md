# Run: 2026-11-18 — post-0.37.0, MCP only, against the published package

**Result: PASS.** Zero hard fails, **zero improvisations** (assessed), 6 assessed docs gaps.

This run was made as part of a design-system inspection and logged here afterwards (D144).
It is **not the `PROMPT.md` ledger task**, and its method is stricter than any earlier run.
Read the trend accordingly.

## Method: stricter than every earlier run

- **Access: the four MCP tools and nothing else** (`search`, `get`, `theme`, `check`). The
  agent had no repo, no `CLAUDE.md`, no `llms.txt` and no `dist/`. That is the variant
  `2026-08-07-b.md` asked for ("run the task … with no repo present") so that a result would
  measure the published artifact alone. Every earlier run measured the trail plus
  `CLAUDE.md`. This one measures what a consumer's agent actually reaches.
- **Package: published 0.37.0**, the version npm and the hosted MCP both served that day.
- **Task: a "Team settings" operator screen**, not the ledger. The screen has an app frame
  using 0.37.0's sliding sidebar and NavBar `brandAlign`, a nav tree with icons, a count and a
  current entry, tabs, and a five-control form with an error state. It also has a sortable
  table with a row menu, a segmented filter, an empty state, pagination, a destructive
  confirmation dialog, and toasts. That covers most of the ledger task's surface (table, row
  actions, pagination, tabs, empty state, transient feedback) and adds the app shell, which
  the ledger task does not touch.
- **Output: 599 lines** (`TeamSettings.tsx`, plus a 31-line `main.tsx` and a 23-line
  `app.css`). The files are kept with the inspection report, outside the repo. Like every
  earlier run, only the scored report is kept here.

## Zero hard fails, verified against the published package

- `tsc --strict --noEmit` against the **published 0.37.0 types** passed with no edits. That
  check validates prop types as well as prop names.
- The screen rendered on the server against the published package: 1 `h1`, 1 table, 1 dialog,
  1 combobox, 39 buttons and 21 icons.
- No hex values, no px or rem literals, no `sm`/`md`/`lg`, no `primary`/`secondary`. There is
  one `accent` button. All five stylesheets are imported in the documented
  order.
- The agent's file was clean in `check` on the first pass.

## Zero improvisations, assessed

`TeamSettings.tsx` imports 53 names (components, icons and `useToast`) and hand-writes almost no markup. A grep
for native elements finds one `<form>` (the consumer's job, since `Field` and `FieldStack` go
inside it) and one `<span>` holding the account name inside the account-menu trigger. It finds
no `div`, no hand-built list, no inline SVG and no rebuilt pattern. Layout uses `Stack`,
`Toolbar` and `.psi-py-*` utilities. The one `style` prop sits on `NavBar` and sets a documented component custom property
(`--psi-button-label-max-width`, valued with a space token), which is what the account-menu pattern
asks for.
`app.css` holds the app-root rules from the installation guide, inside `@layer psi.base`.

## The six assessed docs gaps

1. **Icons are not indexed in the MCP.** `search "IconMoreHorizontal"` returns nothing, `get`
   does not know the id, and `check` skips icons. The agent found icon names by **guessing 52
   of them through `check`**, and chose five navigation icons "by availability, not fit".
   **The most costly finding of this run.** Every generation test since 2026-07-21 has
   stumbled here, and the roster is already in `manifest.icons`.
2. **The pattern presets fail the server's own `check`.** The `destructive-confirm` preset is
   a `<Dialog>` with neither `open` nor `onClose`, and `check` reports both as missing. The
   agent counted 10 such findings across five presets. (D143 addresses this.)
3. **Tag's page carries a generic "Variant guidance" block** that describes `ghost` and
   `outline`, which Tag does not accept. The same block appears on ten pages, including Card's
   and Skeleton's.
4. **`useToast()` has no API table**, and `search "useToast"` finds nothing. The agent worked
   the hook's shape out from an example.
5. **The `destructive-confirm` preset and the Dialog page disagree.** The preset gives Cancel
   `ghost` and no `dismissible`. The page gives Cancel `neutral` with
   `dismissible={false} closeOnEscape`. The agent had to pick one of the two.
6. **`check` suggests `onVolumeChange` for Combobox's `onValueChange`.** Combobox reports its
   value through `onChange`, while RadioGroup, Tabs and SegmentedControl use
   `onValueChange`. When an agent passes the sibling's name, `check` (and `tsc`) answer with a
   DOM media event. The suggestion is misleading, and the naming drift underneath it is real.

Two smaller ones, both recurring and both left uncounted:
- Native props are implied but never stated. Switch's prop table lists only `children`, `ref`
  and `className`, so `checked` and `onChange` come from an example.
- `app.css`'s `body { margin: 0 }` is a guess the agent marked itself. `AppShell` is
  `100dvh` and must mount with no margin around it, and the installation guide does not say
  so.

### Not counted

Pattern parameters, content and theme choices, and the empty-query overview (it trims pattern
summaries to one word and lists 8 of 60 components). That overview is a discoverability
wrinkle the agent worked around in one `search`, and it changed nothing in the output.

## Comparison with earlier runs

The trend in `runs/` is not comparable across this run. The task is different (team settings,
not the ledger), and so is the access (MCP only, not the repo trail plus `CLAUDE.md`). What
carries over:
- **Zero hard fails held** under a stricter method. That is now a property of the published
  artifact, not of the repo the agent happened to be standing in.
- **Zero improvisations held** on a surface the ledger task never exercised: app shell, nav
  tree, segmented filter and combobox.
- **The icon gap has persisted across runs.** The 2026-08-07 (a) run found a missing glyph,
  and this run finds a missing index. The icon now exists, and the agent still cannot discover
  it.

## What this makes next

Documentation and MCP work, smallest first:

1. Index icons in the MCP (`search`, `get`, `check`) from `manifest.icons`.
2. Make the presets pass `check` (D143, in progress).
3. Restrict the generic "Variant guidance" block to components that accept those variants.
4. Give `useToast()` an API table, and make it findable by `search`.
5. Align the `destructive-confirm` preset with the Dialog page's Cancel variant and dismissal
   props.
6. Settle Combobox's value-callback name against its siblings, or teach `check` not to
   suggest a DOM event for it.
7. State native-prop passthrough on component pages, and say in the installation guide that
   `AppShell` needs a margin-free body.
