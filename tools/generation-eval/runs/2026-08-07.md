Every prop the agent reported was cross-checked against `dist/manifest.json` — all present, and
every enum value in vocabulary (`Table size={40}`, `IconButton size={24}`, `Dialog width={400}`
/ `placement="inline-end"`, `Panel padding={24}`, `Toolbar gap={8}`, `MenuItem variant="danger"`,
`Tag variant="accent" subtle`). No hardcoded colours, no px/rem literals, no `sm`/`md`/`lg`, no

Then verified the stronger way: the deliverable was typechecked against the **published 0.13.1

*type*; the compiler cannot. This is worth keeping as the standing check, since it costs nothing

The agent used all nine relevant patterns from `patterns.json` rather than rebuilding them from
primitives, and reached them by reading `patterns.json` before `manifest.json` — the trail
worked as designed.

## The two assessed improvisations — both are the DS shipping a pattern it cannot render

1. **No key/value display component.** `detail-drawer`'s body is the placeholder
   `[key-value summary of the selected record]` and stops there. Nothing in the roster builds it,
   so the agent hand-rolled a native `<dl>`/`<dt>`/`<dd>` grid. This is the drawer pattern's
   *entire body* — the one thing it most needs.
2. **No ellipsis / kebab / "more" icon.** `row-actions` specifies `content: "[icon]"` for its
   trigger, and the 25-icon set has no such glyph (confirmed by listing it). The agent used
   `IconChevronDown` as a stand-in rather than inlining hand-drawn SVG — the right call, and
   still a stand-in.

Both are the same shape of defect and it is a new one: **a shipped pattern whose required parts
do not all exist.** Cycles 1–5 hunted for missing *components* and found them by asking which
patterns had no component at all. Neither of these would have surfaced that way — `detail-drawer`
and `row-actions` both compose only components that exist, which is exactly the "zero gaps"
signal cycle 6 inherited. The patterns validator checks that a pattern's `component` fields
resolve; it does not check that a pattern's *placeholder text* resolves to anything.

### Two reported improvisations assessed as correct behavior

- **The `Stack` flex wrapper.** `packages/react/llms.txt` prescribes exactly this —
  "`.psi-gap-*` utilities set only the gap … Pair them with `display: flex`". The system can
  express it and says how, so it is a recipe followed, not a gap. (A `Stack` component remains a
  legitimate design question; it is not an improvisation.)
- **Native `<h1>`/`<p>` with `.psi-text-*`.** Same reasoning: utilities are the documented
  typography mechanism. Borderline — `empty-state` leaves `headline`/`explanation` as bare
  strings and never says what element to wrap them in — but the mechanism exists and was used.

## The two assessed docs gaps

1. **`filter-toolbar` and `guidance.rules` contradict each other.** The pattern composes `Input`,
   `Select` and `Tag` as siblings in one `Toolbar`; `guidance.rules` says to wrap labeled form
   controls in `Field` and not to hand-roll label rows. `Field` stacks a label above its control,
   so a bare `Tag` in that row misaligns. `table-pagination` sides with `Field`; `filter-toolbar`
   does not. The agent split them across two `Toolbar`s and flagged that the docs do not resolve
   it. They do not.

2. **`packages/react/README.md` omits `utilities.css` entirely** — it lists `psi-react/styles`
   plus `base`, a theme, and `components`, which is four, not five. `llms.txt` is correct.

   This one has a sting: **`CLAUDE.md` asserts that "`packages/react/llms.txt` and
   `packages/react/README.md` had it right all along."** Half of that is false, and it has been
   false since the sentence was written to record the D62 improvisation. The machine trail was
   right and the human-facing README was wrong — the same shape as D68's packaging bug, where
   every doc said `./styles` and only the undocumented spelling worked. Worth noting that the
   agent did **not** trip on this: it read `llms.txt` and imported all five. The README would
   only mislead a human.

## Method note, stated so it is not over-read

The agent was context-free but ran **inside the repo**, so `CLAUDE.md` loaded automatically —
and `CLAUDE.md` states the px size vocabulary, the flat variant list, the no-hardcoded-colours
rule and the five-stylesheet rule. `PROMPT.md` allows docs written for agents, and prior runs
ran under the same condition, so the result is comparable and rule-compliant. But this run
measures **the trail plus `CLAUDE.md`**, not the trail alone. The clean hard-fail score should be
read with that in mind. A genuinely external run — the D68 harness, installing from npm with no
repo present — would measure something stricter, and is the obvious next refinement.
