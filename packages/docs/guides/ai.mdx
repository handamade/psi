Psi publishes its documentation in forms an AI assistant can read. The data comes from the same generated files the build checks, so an assistant reads real props, token formulas and theme values, and not a guess.

## Connect through MCP

The Psi MCP server has four tools. Each returns text and changes nothing: none writes your files or calls a model.

- **Hosted**: Streamable HTTP at `https://psi.kurkin.de/mcp`. Point an MCP client at it. There is nothing to install.
- **Local**: `npx @handamade/psi-mcp` runs a stdio server.

Check your client's documentation for how it takes a server URL or command.

## The four tools

`search(query)` returns short briefs with ids. An empty query returns an overview: the guidance topics, every component by name, the icon count and the composition patterns. Icons are found by what they show as well as by name: `search("delete")` finds `IconTrash`.

`get(id)` returns the docs for one id as markdown. For a docs page it is the same text as the page's `.md` version.

| Id | What `get` returns |
| --- | --- |
| `component:Button` | The component's docs page: examples, props, keyboard and theming |
| `tokens:color` | A token page, with values in every theme |
| `guide:theming` | A guide from these docs |
| `token:bgPrimary` | One token's formula and its value in every theme |
| `topic:variants` | Usage guidance |
| `pattern:<id>` | A composition recipe: parameters, content, gaps, and a preset to paste: JSX, or a small component when the pattern holds state |
| `icon:IconTrash` | One icon: its import line, keywords and props |
| `icons:all` | Every icon with its keywords, and the props they share |
| `hook:useToast` | The component page that tables the hook's API |

A bare name such as `Button` also resolves, without regard to case.

`theme({ color })` derives a light and a dark theme from one brand colour, or from a hue. Both are solved so every text and control pair meets WCAG AA. It returns the CSS to save, how to import it, and the contrast of every pair. To start from a brief rather than a colour, the assistant picks the hue, chroma and radius itself.

`check({ code })` reads JSX and reports where it uses Psi wrongly: a name Psi does not export, an unknown prop, a value outside a prop's allowed values, a missing required prop, a child a slot does not accept, or a missing accessible name. It does not rewrite the code.

## Give your project agent context

```bash
npx @handamade/psi-mcp init --claude
```

This writes a block into `AGENTS.md`, and into `CLAUDE.md` with `--claude`. The block sits between `<!-- psi:agents:start/end -->` markers, so run the command again after you upgrade Psi and your own edits outside the markers stay.

## llms.txt files

Psi also publishes plain-text indexes for tools that read files, not servers:

- `/llms.txt` is the index.
- `/packages/tokens/llms.txt` has the token rules and artifacts.
- `/packages/react/llms.txt` has the component rules and artifacts.
- [`/docs/llms.txt`](/docs/llms.txt) lists every page in these docs as markdown.

## Rules an assistant should follow

The same rules apply to people. They are on [Sizes and variants](/docs/get-started/sizes-and-variants/): sizes are pixel numbers, variants come from a flat list, and `danger` is only for destructive actions.
