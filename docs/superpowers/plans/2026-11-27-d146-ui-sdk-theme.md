# UI SDK bridge (`ui-sdk.css`, D146) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@handamade/psi-tokens/ui-sdk.css`, a generated stylesheet that themes UI SDK's default look with Psi tokens, and gate `borderFocus` at 3:1 in the contrast matrix.

**Architecture:** A typed source map (`src/bridges/ui-sdk.ts`) aliases each `--ui-*` token to one Psi token. A postcss-based extractor (`src/bridges/ui-sdk-ring.ts`) reads the focus-ring rules from the pinned `@ui-sdk/core/web.css`. `scripts/emit-bridges.ts` writes `dist/ui-sdk.css` and `dist/ui-sdk.json` from both. Vitest checks coverage, roles and ring selectors. A Playwright `@interaction` fixture checks both layer orders in a real browser. A Storybook story gives `vr` baselines, and a guide documents the bridge.

**Tech Stack:** TypeScript, tsx build scripts, vitest, postcss 8 + postcss-nested 7, Playwright, Storybook 10, Astro MDX guides, changesets.

**Spec:** `docs/superpowers/specs/2026-11-20-d146-ui-sdk-theme-design.md`. Read its **Amendments, 2026-11-27** section: it overrides the body where they differ.

- `@ui-sdk/core` and `@ui-sdk/react` are pinned **exactly** at `0.1.0-beta.18`, as **devDependencies only**: core in `packages/tokens`, both core and react in `apps/storybook`. Never a dependency or peerDependency. The published `ui-sdk.css` imports nothing.

- Never hardcode colours in component CSS; dist is generated, so never hand-edit it.
- Decision number D146: re-check it is unclaimed on `origin/main` and every `origin/*` branch **when the PR opens** (`git grep -n '^### D146' origin/main -- docs/superpowers/specs`, which must return nothing).
- All five gates before the PR:
  `pnpm build && node tools/check-docs-drift.mjs && pnpm test && pnpm lint && pnpm --dir apps/site build && pnpm test:site`, plus `pnpm test:e2e` for the new fixture. `pnpm vr` passes only in CI; do not run it locally.

```ts
import postcss, { type Rule } from "postcss";
import nested from "postcss-nested";

export type RingRule = { kind: "outline" | "box-shadow"; selector: string };

/** D146 §3: every rule whose `outline` or `box-shadow` draws `var(--ui-ring)`,
 * with nested `&` selectors flattened by postcss-nested. Source order. */
export function extractRingRules(css: string): RingRule[] {
  const root = postcss([nested()]).process(css, { from: undefined }).root;
  const out: RingRule[] = [];
  root.walkDecls((decl) => {
    if (decl.prop !== "outline" && decl.prop !== "box-shadow") return;
    if (!decl.value.includes("var(--ui-ring)")) return;
    const rule = decl.parent;
    if (!rule || rule.type !== "rule") {
      throw new Error(`extractRingRules: ${decl.prop} with --ui-ring outside a rule (${rule?.type})`);
    }
    out.push({ kind: decl.prop as RingRule["kind"], selector: (rule as Rule).selector.replace(/\s+/g, " ") });
  });
  return out;
}
```

import { uiSdkTokenMap, uiSdkColourRoles, uiSdkLeftAlone, UI_SDK_LAYER_LINE, UI_SDK_TAILWIND_LAYER_LINE } from "../src/bridges/ui-sdk.js";
import { extractRingRules } from "../src/bridges/ui-sdk-ring.js";

/** D146 — dist/ui-sdk.css. Generated; edit src/bridges/ui-sdk.ts instead. */
export function emitUiSdkCSS(webCss: string, version: string): string {
  const map = Object.entries(uiSdkTokenMap).map(([k, v]) => `    --ui-${k}: ${v};`).join("\n");
  const rings = extractRingRules(webCss).map(({ kind, selector }) =>
    kind === "outline"
      ? `  ${selector} {\n    outline-width: var(--psi-focus-ring-width);\n    outline-offset: var(--psi-focus-ring-offset);\n  }`
      : `  ${selector} {\n    box-shadow: 0 0 0 var(--psi-focus-ring-width) var(--ui-ring);\n  }`,
  ).join("\n\n");
  return `/* @handamade/psi-tokens/ui-sdk.css (D146), generated. Themes UI SDK's default look with Psi tokens.
 * Built against @ui-sdk/core@${version}. Import it after @ui-sdk/core/web.css, behind this layer line:
 *   ${UI_SDK_LAYER_LINE}
 * Retune it through Psi tokens, never through --ui-* directly. */
@layer psi.ui-sdk {
  :root, :host, [data-psi-theme] {
${map}
  }

${rings}
}
`;
}

export function emitUiSdkJSON(version: string): string {
  return JSON.stringify({
    uiSdkVersion: version,
    layerLine: UI_SDK_LAYER_LINE,
    tailwindLayerLine: UI_SDK_TAILWIND_LAYER_LINE,
    map: Object.entries(uiSdkTokenMap).map(([k, v]) => ({ name: `--ui-${k}`, value: v, role: uiSdkColourRoles[k] ?? null })),
    leftAlone: uiSdkLeftAlone.map((k) => `--ui-${k}`),
  }, null, 2) + "\n";
}

import bridge from "@handamade/psi-tokens/ui-sdk.json";

[UI SDK](https://ui-sdk.dev) is a headless behavior layer. Its optional default look, `@ui-sdk/core/web.css`, is
driven by `--ui-*` custom properties. `@handamade/psi-tokens/ui-sdk.css` sets each of them to a Psi token, so a team
building on UI SDK gets a Psi theme. It is a theme for UI SDK's own components, not a set of Psi components.

## Imports

Import the four token stylesheets, UI SDK's stylesheet, then the bridge. The first line is the contract: UI SDK's
layer comes first and the bridge last, and your own unlayered CSS still beats both.

<pre><code>{`${bridge.layerLine}
@import "@handamade/psi-tokens/base.css";
@import "@handamade/psi-tokens/light.css";
@import "@handamade/psi-tokens/components.css";
@import "@handamade/psi-tokens/utilities.css";
@import "@ui-sdk/core/web.css";
@import "@handamade/psi-tokens/ui-sdk.css";`}</code></pre>

If the app also renders Psi components, import `@handamade/psi-react/styles` as well.

### With Tailwind

UI SDK's Tailwind instructions import `web.css` with `layer(components)`. Use this layer line instead, so Psi's
layers come after Tailwind's `components` and a utility class still wins:

<pre><code>{bridge.tailwindLayerLine}</code></pre>

## What is mapped

<table>
  <thead><tr><th>UI SDK token</th><th>Psi value</th><th>Role</th></tr></thead>
  <tbody>
    {bridge.map.map((m) => (
      <tr><td><code>{m.name}</code></td><td><code>{m.value}</code></td><td>{m.role ?? "size or font"}</td></tr>
    ))}
  </tbody>
</table>

Every colour is one Psi semantic token, and each sits in a role Psi's contrast gate checks. To retune UI SDK, retune
Psi: set the Psi token, never `--ui-*` directly.

## What is left alone

{bridge.leftAlone.map((n, i) => <>{i > 0 && ", "}<code>{n}</code></>)}. The shadow has no Psi token to follow, and
it follows light and dark through the `color-scheme` each Psi theme sets. The icons are mask shapes, so they take
their colour from the element.

## The focus ring

UI SDK draws its focus ring as a 4px outline in `--ui-ring`. The bridge maps that colour to `--psi-border-focus`,
which Psi gates at 3:1 on both surfaces. For each of UI SDK's ring rules it sets the width to
`--psi-focus-ring-width` and the offset to `--psi-focus-ring-offset`, so a focused UI SDK control looks like a
focused Psi one.

## Version

The bridge was built against `@ui-sdk/core@{bridge.uiSdkVersion}`. A later UI SDK may add tokens the bridge does not
map; they keep UI SDK's own values until Psi catches up.
